# ServerGuard 安全审计与修复报告（P0/P1/P2）

> 审计日期：2026-08-17
> 审计目标：以"可能搞崩生产服务器"为标准，全面检查自愈 Agent 的破坏性操作链路
> 方法：三路并行审计（杀进程/重启链路、文件/网络/升级破坏面、新增功能暴露面），所有结论经人工核实后修复
> 结果：**修复 17 项缺陷，全部有 git 提交**；验证通过项同步列出

## 一、修复的缺陷清单

### P0 —— 可直接导致服务器失控/守护静默死亡

| # | 缺陷 | 危害 | 修复 |
|---|---|---|---|
| 1 | Hub 远程 restart / 自动升级后 Agent 优雅退出（exit 0），而 systemd 单元是 `Restart=on-failure` | **守护进程永久静默死亡**——监控自愈全灭直到人工介入 | 单元改为 `Restart=always`（install.sh + service）；远程 restart 加 5 分钟原子冷却防重启风暴 |
| 2 | SecurityGuard 查杀"恶意进程"完全绕过五层安全阀：不查 Kill 预算/熔断/紧急停止/白名单深度校验，黑名单含 `busybox`/`bot`/`ddos` 等泛化名；/tmp 运行即杀 | 误杀合法进程（CI 构建、嵌入式 busybox、爬虫脚本）且绕过一切兜底 | 新增 `killWithApproval`：CheckKillPermission + RecordKill + 拒绝时告警说明；删除泛化黑名单名（busybox-in-/tmp 由可疑目录规则覆盖） |
| 3 | OOM 防护 kill 后无 RecordKill：预算/最小间隔/熔断/"1小时10次急停"全部失明；被杀进程被拉起再膨胀可形成**无限 OOM kill 循环** | 杀进程风暴无人叫停 | 补 RecordKill + 维护窗口/暂停期跳过 OOM kill |
| 4 | PostKillEvaluator 假实现：状态采集返回全零 → 每次 kill 都发假"系统恶化"告警；恶化时也从不真正触发紧急停止（无 sm 引用）；executor 传"异常计数"当负载、"500"当内存 | "越修越糟自动急停"这一兜底形同虚设 | gopsutil 真采集；SetSafetyManager 注入后恶化真正 TriggerEmergencyStop；executor 改自动采集 |
| 5 | 封禁自锁组合拳：①SSH 失联看门狗拨 127.0.0.1:22（永远检测不到失联）②回滚清理 grep 'SG_'（实际规则注释是 serverguard，回滚是空操作）③executor 裸 iptables 无注释无过期 ④security 封禁无 exp 注释（Agent 崩溃后成永久封禁）⑤attackwarn 主力封禁路径无看门狗 | NAT 出口命中阈值后**没有任何自动机制能救回管理员** | ①检测改 ss 统计 22 端口外部已建立连接 ②清理改匹配 serverguard ③④注释带 exp（清扫器可按期清理）⑤attackwarn 接看门狗；另新增**预防层** `platform.IsAdminSSHSource`：封禁目标 IP 是当前已认证登录来源时直接拒绝（who 解析，爆破者不会误保护） |

### P1 —— 可导致数据丢失/保护层失效/引擎卡死

| # | 缺陷 | 危害 | 修复 |
|---|---|---|---|
| 6 | 场景模板 apply：rules.yaml 读失败/解析失败错误被吞 → 带空规则继续写；非原子写 | **用户全部自愈规则被覆盖清零**；断电留半个文件守护规则静默失效 | 存在但读不动即中止；临时文件+rename 原子写；带时间戳备份 |
| 7 | `IsFileBeingWritten` 用 `O_WRONLY\|O_EXCL` 打开——Linux 内核对普通文件忽略 O_EXCL、root 恒可打开，**恒返回 false** | 磁盘清理的"活跃写入保护"名存实亡 | mtime<2min 启发式（配合扩展名白名单足够安全） |
| 8 | ghost_file 幽灵文件清理：磁盘 80% 即批量 SIGTERM/SIGKILL 业务进程 + systemctl restart 任意 unit，全程绕过 SafetyManager | 磁盘一紧张就随机杀业务进程 | autoClean 入口查 ShouldPauseDangerousActions；batchKill 每 PID 过 CheckKillPermission + RecordKill |
| 9 | copytruncate"紧急备份"：defer os.Remove 把压缩备份和原始备份**全部立刻删掉**，告警却谎称"已压缩保存" | 100MB+ 活跃日志截断后内容永久销毁 | 压缩成功保留 .gz、失败保留原文件，绝不两头空 |
| 10 | correlation 引擎：缓冲无硬上限、每条新告警触发 O(n²) 持锁配对、每告警×每事件全量落库（含重复 DDL） | 告警风暴时**事件总线被卡死、队列丢事件、SQLite 写锁拖垮全部存储**——监控在最需要它的时刻失效 | 缓冲 300 条硬上限；配对截断最新 80 条；落库 30s 节流；DDL 每实例一次 |

## 二、验证通过的关键安全不变量（无需修复）

1. **配置默认值 fail-safe**：缺配置/字段缺失时安全默认齐全（预算 5/20、间隔 30s、熔断 3、内存地板 100MB）；预算=0 时拒绝而非放行
2. **系统进程保护**：PID≤2 拒杀；硬白名单含 ssh/systemd/init/cron/nginx/mysql/bt 全套；Agent 不会杀自己；宝塔红线不可配置（config.go 直接报错）
3. **nginx -t 预检**：systemd 重启双路径强制；开机 5 分钟保护
4. **service guard 风暴防护**：per-target 冷却 300s + MaxRetries 5 + 指数退避 + 60s/3 次判风暴放弃 30min；上游宕机先隔离下游
5. **Docker 守护零破坏**：从不 restart/prune/改容器，只告警
6. **磁盘清理白名单**：/www/wwwroot、数据库目录、/etc 在黑名单且不在扫描白名单；不跟随符号链接；只删 .gz/.1/.old 等轮转文件
7. **storage 维护循环**：只删自己 DB 的行，审计 WORM 保留；VACUUM 用 incremental_vacuum 轻量路径
8. **OOM 优先级**：Agent 自设 oom_score_adj=100 + systemd MemoryMax 硬闸——失控时 OOM Killer 先杀 Agent 而非业务进程
9. **V4.0 新功能认证**：notify/reply、onboarding、scene-templates、incidents、llm、export、import、db、servers/:id/command 全部在鉴权组内；/ws/agent 空密钥 fail-closed；LLM 默认关闭且 key 不出 JSON
10. **证书续期只 reload 不 restart**，失败保持旧 worker；多 CA 降级失败旧证书由 acme.sh 目录兜底

## 三、遗留观察项（不影响安全，建议后续处理）

1. RBAC 角色定义了但路由未强制（viewer 可调写接口）——单管理员部署影响小
2. PID 复用竞态：kill 前未做身份复验（Linux 上白名单深度检查部分缓解）——完整修复需 create_time 比对
3. decider 规则型 kill 预检传 pid=0 被 pid≤2 保护恒拒（fail-closed 方向的功能坏死，无安全风险）
4. incidents 表无保留期自动清理（增长缓慢，可加入 downsampler）
5. `/metrics` 默认无 token 公开（仅系统指标，无敏感数据）
6. LLM 开启后告警内容（含攻击者 IP）会发往外部 API——文档应提示
7. `tmp/reseed.go` 等脚本含生产明文密码（**需用户手动删除并改密码**）
