# 凌晨3点磁盘满了MySQL崩了，但我睡到了早上8点

## 一个真实的故事

上个月某个周三，凌晨3点17分。

我的服务器磁盘使用率冲到了97%。

一个叫wvp的日志文件，悄无声息地从500MB涨到了18个G，把整个磁盘撑爆了。

MySQL写不进去数据了。网站打不开了。用户开始报错了。

以前遇到这种事，流程是这样的：

1. 手机收到告警短信
2. 睡眼惺忪爬起来
3. 打开电脑，SSH连服务器
4. 查了半天才发现是日志文件太大
5. 手动清理，重启MySQL
6. 折腾40分钟，终于恢复
7. 回床上翻来覆去睡不着了

这次不一样。

我装了一个叫ServerGuard的小工具。

凌晨3点17分，磁盘涨到95%的时候，它自动干了一件事：**清理了30天以前的旧日志和压缩文件**。

磁盘从97%降到了63%。MySQL没崩。网站没断。用户根本不知道发生过什么。

早上8点，我醒来，打开微信，看到一条消息：

> 📋 每日巡检报告
> 昨晚03:17，磁盘使用率达到95%，已自动清理旧日志（释放34GB），MySQL未受影响。
> 当前磁盘使用率：63%，服务器健康评分：92分。

我翻了个身，继续睡。

## 它到底做了什么？

说白了就是一件事：**服务器出问题的时候，它替你动手，而不是只给你发条告警然后干等着。**

你可能要说了，我装了宝塔啊，宝塔不是有监控吗？

宝塔确实有监控。但宝塔的监控就是告诉你"你的磁盘满了"，然后呢？**然后你自己去清。** 大半夜的，你去清吗？

Zabbix更离谱。装一个Zabbix要吃掉600MB内存，配一个监控模板要半小时，最后它也只能告诉你"服务器挂了"。**知道了又能怎样？还不是得爬起来修。**

ServerGuard不一样。它就16MB大小，装上去不用管了。它能干的事：

**磁盘快满了** → 自动清理旧日志，不碰你的数据库和网站源码
**某个进程CPU飙到80%** → 自动降优先级，实在不行重启它
**MySQL/Redis挂了** → 自动检测端口，发现挂了自动拉起来
**SSL证书快到期了** → 提前14天自动续期，续完自动刷新Nginx
**有人暴力破解你SSH** → 5次失败自动封IP，不封内网IP
**日志文件涨到500MB了** → 自动轮转压缩，不会等它涨到18GB
**有人在你服务器上传了木马** → 扫描到直接杀掉进程

每一步都会发微信通知你，告诉你"发生了什么、我怎么处理的"。

## 它会不会搞坏我的服务器？

这是所有人第一个问题。

说实话，我最开始也担心。服务器这种东西，多一事不如少一事。你一个自动修复的工具，万一误操作呢？

我用了之后发现，它比我小心多了。它有五层安全机制：

**第一层：它自己很省资源。** 内存限制80MB，CPU限制5%。不会因为自己监控把服务器搞慢。

**第二层：服务器忙的时候它不动手。** CPU超过95%的时候，它进入"存活模式"，只看不动。

**第三层：杀进程有预算。** 每小时最多杀15个进程，连续失败3次自动停手。

**第四层：操作完盯着看。** 杀完进程观察60秒，如果服务器更差了，立刻停手。

**第五层：一键紧急停止。** 你觉得不对劲，点一个按钮，所有自动修复全停。

还有一件事让我特别放心：**它永远不会碰nginx、MySQL、宝塔面板这些关键进程。** 白名单里有45+个系统进程，碰都不碰。

它甚至有一个"学习模式"——刚装好的时候只看不动手，跑两天你觉得告警合理了，再让它自动修复。

## 安装只要30秒

一行命令搞定：

```bash
curl -sSL https://sg.jjtt.net/install.sh | bash
```

装完打开浏览器，看到一个面板，左边是服务器健康评分（0-100分），中间是CPU/内存/磁盘的实时图表，右边是告警列表。

第一步：改密码。
第二步：填一个微信推送的Key（免费的，去server酱注册一个就行）。
第三步：开学习模式，跑两天看看告警合不合理。

就这么简单。不需要配什么监控模板，不需要写什么配置文件。它自动检测你服务器上跑着什么服务（Nginx、MySQL、宝塔……），自动纳入守护。
