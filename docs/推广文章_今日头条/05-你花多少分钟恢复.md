# 服务器出了问题，你花了多少分钟才恢复？

## 做个算术题

假设你管着3台服务器。每台一个月平均出2次故障。一年就是72次故障。

每次故障从"发现问题"到"恢复服务"，你需要多久？

- 手机收到告警/用户投诉：5分钟
- 爬起来开电脑：5分钟
- SSH连服务器：2分钟
- 查日志定位问题：10-30分钟
- 修复问题：5-20分钟
- 验证恢复：5分钟

**最少30分钟，多的话1-2小时。**

72次 × 平均45分钟 = **3240分钟 = 54小时 = 2.25天**

你一年光处理服务器故障，就花掉2天多的时间。

而且这些里面有一半发生在凌晨或周末。

## 什么样的故障最常见

我管了5台服务器一年多，遇到的所有故障，无外乎这五类：

### 第一类：磁盘满了

占比最大。

原因五花八门：日志文件暴涨、临时文件没清、缓存撑爆、数据库二进制日志太多。

最离谱的一次，一个日志文件涨到了18GB，把整个磁盘撑爆了。MySQL写不了数据，网站打不开。

**处理方式：** 手动找到大文件 → truncate或删除 → 重启受影响的服务。

**费时：** 15-40分钟。主要花在"找哪个文件占了空间"上。

### 第二类：服务挂了

某个进程突然死了。Nginx、MySQL、Redis、你的应用服务都有可能。

有时候是内存泄漏，有时候是遇到了bug，有时候是OOM Killer随机杀进程。

**处理方式：** 发现端口不通 → 查日志 → 手动重启。

**费时：** 10-30分钟。如果你凌晨才发现的话，加15分钟起床时间。

### 第三类：CPU/内存爆缸

某个进程突然CPU飙到200%+，或者内存泄漏吃光了所有内存。

我有一次一个Python推理服务CPU干到了273%，整台服务器卡死，所有服务全部受影响。

**处理方式：** SSH连上 → top命令找罪魁祸首 → kill -9 → 确认其他服务恢复。

**费时：** 15-45分钟。服务器卡死的时候SSH都连不上，干等着。

### 第四类：被攻击

SSH暴力破解、网站被CC、被人上传了木马。

有一次我的SSH被人字典攻击，成功入侵后挂了挖矿程序。服务器CPU天天100%，查了好久才发现。

**处理方式：** 查auth.log → 封IP → 杀木马进程 → 改密码 → 检查后门。

**费时：** 30分钟到2小时。如果被入侵了还要全面排查，一个下午就没了。

### 第五类：证书过期

宝塔免费SSL证书3个月就过期，忘了续就是"不安全"红叉。

**处理方式：** 登录宝塔 → 重新申请证书 → 等校验 → 部署。

**费时：** 5-10分钟。但如果你没发现的话，用户看到红叉直接走人了。

## 那它会不会乱来

这是所有人最担心的。

它的安全设计是这样的——

**三层安全策略：**

- ✅ **自动执行：** 杀OOM非白名单进程、清旧日志、封IP、杀木马/挖矿、续证书、重启服务
- ⚠️ **只告警不动手：** WebShell检测、cron篡改、文件完整性变化、网络异常
- 🚫 **永不触碰：** 杀nginx/MySQL/宝塔、删/tmp、删/www、yum/apt clean

**五层保护机制：**

1. 自己资源限制：内存<80MB，CPU<5%
2. 服务器忙时只看不修：CPU>95%进入存活模式
3. 操作有预算：杀进程每小时最多15次
4. 操作完盯着看：60秒内服务器变差就停手
5. 一键紧急停止：觉得不对劲，点一个按钮全停

还有一个**学习模式**。刚装好的时候，它只看不动手。跑两天你觉得告警合理了，再让它自动修。

**该出手时不犹豫，不该碰的不碰，不确定的交给你决定。**
